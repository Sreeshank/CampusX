# Configuration and payload examples
These files are reference examples, not a runnable source project. Copy appropriate files into the actual app and complete setup before use. No API has been deployed or tested by creating this documentation.

- frontend.env.example: all required public Web app configuration and optional later keys.
- gitignore.example: merge into repository .gitignore before your first commit.
- firebase-client.example.ts: SDK initialization and local emulator connections. Set demo-campusx as the project ID with demo values when using the Emulator Suite; otherwise use real development config.
- firebase-hosting.example.json: merge only hosting/emulators sections into the firebase.json generated by firebase init; retain generated functions/rules/index settings. This is not a complete Firebase deployment config.
- listing-payload.example.json: sample sale listing input; replace image path and idempotency key with valid values. ₹300 equals 30000 paise.
- ride-payload.example.json: sample one-passenger offer; replace the future time, configured pickup IDs and idempotency key.
- FEATURE_TASK.md: duplicate for each assigned implementation issue.

Server functions use managed application default credentials. Do not create a .env template containing a private key merely to satisfy a field list. Genuine third-party secrets introduced later belong in server secret management and are never prefixed VITE_.
